%
% crash_attribution_no_carry_buggy.tex
%
% A Z specification of display-crash attribution: which scenes the Hub blames
% when the display ends a dial.  The design's rulings T10 to T14 are stated in docs/crash_attribution.tex.
%
% The rulings it models: T10 (a death is charged from the dead dial's own ack
% ledger, whoever discovers it; a Hub-ended dial charges nothing; an empty
% ledger charges nothing), T11 (the display installs a scene on receipt but
% holds its ack until the next completed buffer swap: an ack means a frame
% survived the scene), and T12 (a Hub-ended dial's non-empty ledger joins a
% carried suspect set, which a display-ended death charges and any ack read on
% a later dial clears).  Deaths are queued at discovery and charged first at the
% replicator's next push or idle tick.  T13 adds a third retire cause,
% unresponsive (a dial the probe gave up on while the display may live): queued
% as a display death and carried as a Hub end.  T14 splits the read into Recv and
% Deliver and guards a display-ended capture on both being empty.
%
% The code it governs: src/punt_lux/domain/hub/{batch_sender,recovery,
% display_connection,dial_generation,reply_sink,liveness_probe,replicator,
% death_charger}.py, and src/punt_lux/display/render_loop.py (the ack).  ADRs:
% DES-102 (attribution, isolation and quarantine), DES-093 (the Hub never
% controls the display's process), and the companion model
% listener_lifecycle.tex (a dial's generation, its ledger and its single end).
%
% This is the CONTROL, not the fixed design: the ack is held until the swap
% (T11) but nothing is carried: DiscoverHub adds nothing to the carried set,
% DiscoverUnrCharge leaves it alone, and a display-ended death charges its own
% ledger only.
%
% Violates A1 through the Hub's retire, in 9 operations (918 states):
%   PushStart; Redial; Send(1); Install(1); HubEnd; DiscoverHub(drepl); Redial;
%   CrashFrame; DiscoverQuiet(drepl)
% and A1w, in 12 operations (6430 states):
%   PushStart; Redial; Send(1); Install(1); HubEnd; DiscoverHub(drepl); Redial;
%   Send(2); CrashFrame; PushEnd; DiscoverCharge(drepl); Charge(2)
% and through the probe's retire (T13), A1w with the goal conjoined with
% ended(1)=eunr, in 12 operations (6546 states):
%   PushStart; Redial; Send(1); Install(1); Unresponsive; DiscoverUnrCharge(drepl);
%   Redial; Send(2); CrashFrame; PushEnd; DiscoverCharge(dother); Charge(2)
% The scene is installed and held, the dial is retired while the display lives,
% the display crashes painting it on the next dial; that dial's ledger holds only
% scene 2, which is charged, and the culprit is not.  A2, A3 and A4 hold (30717 states).
%
% Type-check:  fuzz docs/crash_attribution_no_carry_buggy.tex
% Model-check (one negated goal at a time; the goals are those of
% docs/crash_attribution.tex, Section Verification):

%     -p MAX_OPERATIONS 200 -goal "<negated goal>"

This is a control, not the design.  The design's rulings T10 to T14 are stated in docs/crash_attribution.tex.  It is the design's
specification with the one change named in the header comment, and nothing
else; its purpose is to show that the invariants of the design fail when
that change is made, which is what makes their passing meaningful.

\begin{axdef}
  maxDial : \nat \\
  maxScene : \nat \\
  thr : \nat \\
  poison : \nat
\where
  maxDial = 2 \\
  maxScene = 2 \\
  thr = 2 \\
  poison = 1
\end{axdef}

\begin{zed}
  Sc == 1 \upto maxScene
\end{zed}

\begin{zed}
  Dl == 0 \upto maxDial
\end{zed}

\begin{zed}
  LV ::= lup | ldown
\end{zed}

\begin{zed}
  ENDT ::= enone | edisp | ehub | eunr
\end{zed}

\begin{zed}
  DISC ::= drepl | dother
\end{zed}

\begin{zed}
  PH ::= pidle | ppush
\end{zed}

\begin{axdef}
  bump : 0 \upto thr \fun 0 \upto thr
\where
  bump = \{ 0 \mapsto 1, 1 \mapsto 2, 2 \mapsto 2 \}
\end{axdef}
