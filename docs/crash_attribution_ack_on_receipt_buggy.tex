% A Z specification of display-crash attribution: which scenes the Hub blames
% when the display ends a dial.  The design's rulings T10, T11 and T12 are stated in docs/crash_attribution.tex.
%
% The rulings it models: T10 (a death is charged from the dead dial's own ack
% ledger, whoever discovers it; a Hub-ended dial charges nothing; an empty
% ledger charges nothing), T11 (the display installs a scene on receipt but
% holds its ack until the next completed buffer swap: an ack means a frame
% survived the scene), and T12 (a Hub-ended dial's non-empty ledger joins a
% carried suspect set, which a display-ended death charges and any ack read on
% a later dial clears).  Deaths are queued at discovery and charged first at the
% replicator's next push or idle tick.
%
% The code it governs: src/punt_lux/domain/hub/{batch_sender,recovery,
% display_connection,dial_generation,reply_sink,liveness_probe,replicator,
% death_charger}.py, and src/punt_lux/display/render_loop.py (the ack).  ADRs:
% DES-102 (attribution, isolation and quarantine), DES-093 (the Hub never
% controls the display's process), and the companion model
% listener_lifecycle.tex (a dial's generation, its ledger and its single end).
%
% This is the CONTROL, not the fixed design: the display sends each scene's ack
% at receipt, in the Install step, and a completed swap sends nothing.  This is
% the code as it stands (render_loop.py, _handle_scene).  The ack then means
% 'received', not 'a frame survived it'.
%
% Violates A1, in 7 operations (155 states, breadth-first):
%   PushStart; Redial; Send(1); Install(1); ReadAck(1); CrashFrame;
%   DiscoverQuiet(drepl)
% goal  #g.(g:pcrash & g:settled & g/:dom(dqown) & (1|->g)/:chargedOn
%                     & (1|->g)/:carriedOn)
% The scene is acked, then the display dies painting it; the ledger is empty and
% nothing is charged (gvr's trace).  In batching mode A1w (the same goal with a
% scene charged for the death) is violated too, in 10 operations (888 states):
%   PushStart; Redial; Send(1); Send(2); Install(1); CrashFrame; ReadAck(1);
%   DiscoverCharge(drepl); PushEnd; Charge(1)
% the innocent scene 2 is charged and the culprit is not.  A2, A3 and A4 hold
% (each searched alone: no counter example, 12334 states).
%
% Type-check:  fuzz docs/crash_attribution_ack_on_receipt_buggy.tex
% Model-check (one negated goal at a time; the goals are those of
% docs/crash_attribution.tex, Section Verification):

This is a control, not the design.  The design's rulings T10, T11 and T12 are stated in docs/crash_attribution.tex.  It is the design's
specification with the one change named in the header comment, and nothing
else; its purpose is to show that the invariants of the design fail when
that change is made, which is what makes their passing meaningful.

\begin{axdef}
  maxDial : \nat \\
  maxScene : \nat \\
  thr : \nat \\
  poison : \nat
\where
  maxDial = 2 \\
  maxScene = 2 \\
  thr = 2 \\
  poison = 1
\end{axdef}

\begin{zed}
  Sc == 1 \upto maxScene
\end{zed}

\begin{zed}
  Dl == 0 \upto maxDial
\end{zed}

\begin{zed}
  LV ::= lup | ldown
\end{zed}

\begin{zed}
  ENDT ::= enone | edisp | ehub
\end{zed}

\begin{zed}
  DISC ::= drepl | dother
\end{zed}

\begin{zed}
  PH ::= pidle | ppush
\end{zed}

\begin{axdef}
  bump : 0 \upto thr \fun 0 \upto thr
\where
  bump = \{ 0 \mapsto 1, 1 \mapsto 2, 2 \mapsto 2 \}
\end{axdef}

\begin{schema}{CA}
  cur : \nat \\
  up : LV \\
  phase : PH \\
  ended : Dl \fun ENDT \\

  flight : \power Sc \\
  sent : Dl \fun (\power Sc) \\
  acked : Dl \fun (\power Sc) \\
  carry : \power Sc \\
  dqown : Dl \pfun (\power Sc) \\
  dqcar : Dl \pfun (\power Sc) \\
  settled : \power Dl \\
  dirty : \power Sc \\
  strikes : Sc \fun (0 \upto thr) \\
  chargedOn : Sc \rel Dl \\
  carriedOn : Sc \rel Dl \\
  times : Dl \fun (0 \upto 2) \\

\end{schema}
